## Passo 0 — medir o gate `crap` num projeto sem código (antes de qualquer código)
Risco R1 do plano (ADR 0015, "não verificado"): num projeto sem código, o `bob.yaml` gerado tem `include: ["."]`, e o gate `crap` pode sair `4` por ferramenta. Meça isso primeiro, com o `bob` da `main` (`0d85510`, que já tem `init_config`) e sem mudar nenhum arquivo do repo. Na raiz do checkout da branch, ainda sem mudanças:
```sh
E=$(mktemp -d); H=$E/home; mkdir -p "$H"
python3 -m venv "$E/venv" && "$E/venv/bin/pip" install -q .
P="$E/venv/bin:/usr/bin:/bin"
mkdir -p "$E/p0" && cd "$E/p0" && git init -q -b main
git config user.email e2e@example.invalid && git config user.name e2e
printf '%s\n' '# leia' > README.md && git add -A && git commit -qm init
env -i HOME="$H" LANG=C.UTF-8 PATH="$P" "$E/venv/bin/python" -c \
  'from pathlib import Path; from bob_quality.init_config import write_default_config as w; print(w(Path(".")))'
cat bob.yaml
env -i HOME="$H" LANG=C.UTF-8 PATH="$P" bob check --base HEAD --gates crap; echo "EXIT:$?"
cat .bob/report.md
```
Depois, volte à raiz do checkout (`cd -`) e apague `$E` se quiser; nada do passo 0 entra no repo.
