## Objetivo
`curl -fsSL <base>/latest/download/install.sh | sh`, na raiz de um projeto git, confere os pré-requisitos sem escrever nada, baixa a release, confere o sha256 do wheel, instala o venv da versão, liga o launcher e termina com `exec bob setup`.

## Forma do arquivo
- Caminho `scripts/install.sh`, modo `100755` no git. UTF-8, LF, termina com `\n`.
- Linha 1: `#!/bin/sh`. Linha 2: comentário `# bob install.sh: comando único (CT2). POSIX sh; sem bashismos.` Linha 3: `set -u`.
- Logo depois, as linhas de fonte única, nesta ordem, uma por linha, exatas (regex `^NOME='(.*)'$`):
  ```
  STEPS='projeto plataforma python node ferramentas versão download integridade pacote launcher setup'
  DEFAULT_API='https://api.github.com/repos/fazedordecodigo/bob/releases/latest'
  DEFAULT_DOWNLOAD='https://github.com/fazedordecodigo/bob/releases/download'
  CURL_OPTS='-fsSL --connect-timeout 15 --max-time 300 --retry 2'
  PIP_OPTS='--disable-pip-version-check --no-input'
  NODE_FLOOR='22.18.0'
  NODE_BELOW='23'
  PYTHON_FLOOR='3.10'
  ```
  (`perfil` e `PROFILE_LINE` entram com o U6, I14.) Esses valores não se repetem literalmente em nenhum outro lugar do script.
- Depois, só definições de função. A última linha do arquivo é exatamente `main "$@"` (proteção contra download truncado no `curl | sh`).
- Função obrigatória `resolve_bob_home() {` … `}` (abre e fecha em linhas próprias, `}` na coluna 1), autocontida: lê só `BOB_HOME`, `XDG_DATA_HOME`, `HOME`; imprime o root no stdout e devolve 0; `BOB_HOME` relativo → não imprime nada e devolve 1. Regra igual a `user_dirs.bob_home` (R1 da T3), e remove UMA barra final de `BOB_HOME` e de `XDG_DATA_HOME` antes de usar.
- Comandos externos permitidos (lista fechada): `uname git python3 node npm curl sha256sum shasum mktemp rm mkdir ln readlink cat awk grep sed tr id`. Tudo o mais é builtin do `sh` POSIX (`command -v`, `printf`, `case`, `pwd -P`, `cd`, `exec`, `trap`, `read`). Sem `echo -e`, `[[`, `local`, `$'…'`, arrays, `source`, `function`.

## Regras de comportamento (R1–R20)
| # | Regra |
|---|---|
| R1 | Args: `--lang <v>`, `--help`. Outro arg → `usage_unknown`. `--lang` sem valor → `usage_lang_value`. Idioma: `--lang`, senão `BOB_LANG`, senão `en`; valor fora de {`en`, `pt-BR`} → `usage_lang_invalid` (essa mensagem sai em en). Uso inválido sai `4` antes de qualquer outra checagem. `--help` imprime o uso (tabela "Ajuda") no stdout e sai `0`, sem checar nada. |
| R2 | `BOB_HOME` calculado por `resolve_bob_home` logo depois dos args; código 1 → `bob_home_relative`, `4`. |
| R3 | Passos na ordem de `STEPS`; para no primeiro que falha (exit `4`, uma linha no stderr). Cada passo ok imprime `install: <passo>: ok` no stdout; `versão` imprime `install: versão: <tag>`; `setup` não imprime (é o `exec`). |
| R4 | `projeto`: `command -v git` → senão `git_missing`. `git rev-parse --show-toplevel` (stderr descartado) igual a `pwd -P` → senão `not_root` com `dir` = `pwd -P`. |
| R5 | `plataforma`: `uname -s` ∈ {`Linux`, `Darwin`} e `uname -m` ∈ {`x86_64`, `amd64`, `aarch64`, `arm64`} → senão `platform`. |
| R6 | `python`: `command -v python3` → senão `python_missing`. Versão = saída de `python3 -c 'import sys; print("%d.%d.%d" % sys.version_info[:3])'`; `(major, minor) < PYTHON_FLOOR` → `python_old`. `python3 -c 'import venv, ensurepip'` (stderr descartado) ≠ 0 → `python_venv`. |
| R7 | `node`: `command -v node` → senão `node_missing`. `node --version` precisa casar `^v[0-9]+\.[0-9]+\.[0-9]+$` e `NODE_FLOOR ≤ v < NODE_BELOW.0.0` (comparação numérica por campo) → senão `node_out` com `found` = texto como veio. `command -v npm` → senão `npm_missing`. |
| R8 | `ferramentas`: `command -v curl` → senão `tool_missing name=curl`. `sha256sum` ou `shasum` → senão `tool_missing name=sha256sum`. Guarda qual achou (`sha256sum` tem preferência). |
| R9 | Os passos `projeto` a `ferramentas` não criam, apagam nem alteram nenhum arquivo, em lugar nenhum. |
| R10 | `versão`: `BOB_RELEASES_URL` não vazia → remove UMA barra final; precisa casar `https://*`, `http://127.0.0.1`, `http://127.0.0.1[:/]*`, `http://localhost` ou `http://localhost[:/]*` → senão `url_not_allowed`; `API=$R/api/releases/latest`, `DL=$R/download`. Vazia → `API=$DEFAULT_API`, `DL=$DEFAULT_DOWNLOAD`. Depois cria o temporário `mktemp -d "${TMPDIR:-/tmp}/bob-install.XXXXXX"` (falha → `tmp_failed`) e um `trap` que o apaga em `EXIT`, `INT`, `TERM`. `BOB_VERSION` não vazia → precisa casar `^v[0-9]+\.[0-9]+\.[0-9]+$` (senão `version_invalid`) e é a tag; a API não é chamada. Vazia → `curl $CURL_OPTS -H 'Accept: application/vnd.github+json' -w '%{http_code}' -o <tmp>/latest.json "$API"`; curl ≠ 0 → `api_failed`; `tag_name` lido com `python3` (`json`); ausente ou fora de `^v[0-9]+\.[0-9]+\.[0-9]+$` → `api_failed` com `status=invalid response`/`resposta inválida`. |
| R11 | `{status}` nas mensagens de rede: `HTTP <código>` quando o `%{http_code}` ≠ `000`; senão `curl <código de saída do curl>`. |
| R12 | `download`: `X = tag sem v`; `WHL=bob_quality-$X-py3-none-any.whl`; baixa `$DL/$TAG/$WHL` e `$DL/$TAG/SHA256SUMS` para o temporário, nesta ordem, com `curl $CURL_OPTS -w '%{http_code}' -o …`. HTTP 404 → `download_missing` (`tag`, `asset`); outro erro → `download_failed` (`url`, `status`). |
| R13 | `integridade`: `want` = 1º campo da linha do `SHA256SUMS` cujo 2º campo é `$WHL` (`awk -v f="$WHL" '$2 == f { print $1 }'`); `got` = `sha256sum` (ou `shasum -a 256`) do wheel. `want` vazio ou ≠ `got` → `integrity` (`file=$WHL`). Até aqui, nada fora do temporário foi escrito. |
| R14 | `pacote`: `VD=$BOB_HOME/versions/$X`. `VD/.complete` existe e o conteúdo (sem o `\n`) = `got` → reusa (nada é escrito). Senão: `rm -rf VD`, `mkdir -p VD`, `python3 -m venv VD/venv`, `VD/venv/bin/python -m pip install $PIP_OPTS <tmp>/$WHL`; qualquer falha → `rm -rf VD` e `pip_failed`. Sucesso → grava `printf '%s\n' "$got" > VD/.complete` por último. `current` não muda neste passo. |
| R15 | `launcher`: `mkdir -p $BOB_HOME/bin $HOME/.local/bin`; `ln -s "versions/$X" $BOB_HOME/current.tmp` (antes, `rm -f` dele); `VD/venv/bin/python -c 'import os, sys; os.replace(sys.argv[1], sys.argv[2])' current.tmp current`; `ln -sfn ../current/venv/bin/bob $BOB_HOME/bin/bob`. `$HOME/.local/bin/bob`: symlink com `readlink` = `$BOB_HOME/bin/bob` → nada; existe e é outra coisa → imprime `launcher_warning` no stdout e não toca; não existe → `ln -s "$BOB_HOME/bin/bob" "$HOME/.local/bin/bob"`. Qualquer falha → `launcher_failed` (`path` do que falhou; `err` = 1ª linha do stderr do comando, ou `unknown error`/`erro desconhecido`). |
| R16 | `setup`: apaga o temporário e desarma o `trap`; `exec "$BOB_HOME/bin/bob" setup --lang "<idioma>" </dev/null`. O código de saída do `install.sh` é o do `bob setup`. |
| R17 | Sem `sudo`, sem pedir senha, sem ler stdin (o stdin é o script no `curl | sh`). A palavra `sudo` não aparece no arquivo. |
| R18 | `BOB_VERSION` não aparece no texto da ajuda nem em mensagem nenhuma, exceto em `version_invalid`. |
| R19 | Nenhum arquivo do projeto (cwd) é criado, apagado ou alterado pelo `install.sh` (o `bob setup` é quem escreve no projeto). |
| R20 | Mensagens: função `say <id> [args…]` (ou equivalente) com en e pt-BR lado a lado no script; erros vão para o stderr; progresso e aviso para o stdout. Textos exatos na tabela. |
