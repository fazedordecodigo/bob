# Changelog

## Unreleased

`bob doctor` reads the npm versions and the Node range from the `package.json` packaged with bob. A bump of `package.json` and `package-lock.json` is enough, with no code change. The doctor reads each npm tool from bob's own prefix only. A project's `node_modules` and `node_modules/.bin` do not change the result. If the packaged `package.json` cannot be read, the doctor prints one stderr line, as in `bob doctor: package.json: could not read <path> (<error>). Reinstall bob.`, and exits `4`.

O `bob doctor` lê as versões npm e a faixa do Node do `package.json` empacotado com o bob. Um bump de `package.json` e `package-lock.json` basta, sem mudar código. O doctor lê cada ferramenta npm só do prefixo do próprio bob. O `node_modules` e o `node_modules/.bin` do projeto não mudam o resultado. Se o `package.json` empacotado não puder ser lido, o doctor imprime uma linha no stderr, como em `bob doctor: package.json: não consegui ler <caminho> (<erro>). Reinstale o bob.`, e sai com `4`.

`homepage` and `repository` in the Cursor manifest must be an `http` or `https` URI with a host and no credentials. Leading or trailing whitespace, a blank or whitespace host (`http:// /x`, `https://%20/`), and an out-of-range port such as `99999` fail with code `uri` and do not crash the validator. The publish workflow checks out with `persist-credentials: false`.

`homepage` e `repository` no manifesto do Cursor têm de ser um URI `http` ou `https` com host e sem credencial. Espaço no começo ou no fim, host em branco ou só com espaço (`http:// /x`, `https://%20/`) e porta fora da faixa, como `99999`, falham com o código `uri` e não derrubam o validador. O workflow de publicação faz o checkout com `persist-credentials: false`.

The DRY gate can fail. `duplication.new_clones` is `warn`, the default, or `fail`. Without the new keys, a new clone stays a warning and the exit stays `0`. In fail mode, the gate fails with exit `1` when the new clones that pass `duplication.min_similarity` and `duplication.min_lines` exceed `duplication.max_new_clones` (default `0`). The reason names the key and the ceiling, as in `1 new clone exceeds duplication.max_new_clones 0`. The two filters apply in warn mode too, and a clone they drop stays out of the report. `bob dry` and `bob check` accept `--dry-fail` and `--max-new-clones N`, which override the file for that run. A negative `--max-new-clones`, or an invalid value in the new keys, exits `4` and writes no report. The pre-push hook is unchanged.

O gate DRY pode falhar. `duplication.new_clones` é `warn`, o padrão, ou `fail`. Sem as chaves novas, um clone novo continua em aviso e o exit continua `0`. No modo fail, o gate falha com exit `1` quando os clones novos que passam em `duplication.min_similarity` e `duplication.min_lines` passam de `duplication.max_new_clones` (padrão `0`). O motivo cita a chave e o teto, como em `1 new clone exceeds duplication.max_new_clones 0`. Os dois filtros valem também no modo warn, e um clone que eles descartam fica fora do relatório. `bob dry` e `bob check` aceitam `--dry-fail` e `--max-new-clones N`, que vencem o arquivo nessa execução. Um `--max-new-clones` negativo, ou um valor inválido nas chaves novas, sai com `4` e não grava relatório. O hook pre-push não muda.

Um `paths.include` omitido ou vazio continua sendo `src` e não é verificado.

Language detection does not follow symlinks. A symlink to a file or a directory does not select a language, and a symlink that points back at a parent does not loop. `paths.exclude` matches a path prefix or a path component. It is not a glob. An entry `*.py` does not exclude `src/app.py`.

A detecção de linguagem não segue symlink. Um link para arquivo ou diretório não escolhe linguagem, e um link que aponta de volta para um pai não entra em ciclo. `paths.exclude` casa por prefixo de caminho ou por componente. Não é glob. A entrada `*.py` não deixa `src/app.py` de fora.

Omitting `languages`, or setting it to null, detects the list from files under `paths.include` and outside `paths.exclude`. `.py` selects `python`. `.ts`, `.tsx`, `.js`, `.jsx`, `.mjs`, and `.cjs` select `typescript`, in that order. If none of those files exist, the result stays `[python]`. An explicit list is kept as written. A missing `bob.yaml`, with no `--config`, uses the same detection. A `--config` path that is not a file still exits `4` and writes nothing.

`languages` omitido ou nulo é autodetectado pelos arquivos em `paths.include`, fora de `paths.exclude`. `.py` escolhe `python`. `.ts`, `.tsx`, `.js`, `.jsx`, `.mjs` e `.cjs` escolhem `typescript`, nessa ordem. Sem nenhum desses arquivos, o resultado continua `[python]`. Uma lista explícita permanece como foi escrita. Um `bob.yaml` ausente, sem `--config`, usa a mesma detecção. Um `--config` que não é arquivo continua saindo com `4` e não grava nada.

Um `--config` inexistente sai com `4` em `check`, `crap`, `dry`, `deps` e `mutate`. O stderr em inglês cita o caminho, como em `config file not found: <caminho>`, e a execução não grava relatório. Um `bob.yaml` ausente, sem `--config`, continua nos padrões.

A mutation waiver id is `file::function`, for every survivor of that function, or `file::function::<description>`, for one survivor ([#25](https://github.com/fazedordecodigo/bob/issues/25), [ADR 0006](docs/adr/0006-chave-estavel-do-waiver.md)). The description is the mutant's operator with the outer spaces stripped: the `mutmut show` diff for Python, and `{mutatorName}@{line}:{column}-{line}:{column}` plus ` -> {replacement}` when present for TypeScript. The exact form exists only when no other survivor of the function has the same description. The survivor table's first column is now Target, and `survivors[].target` in `report.json` holds the same value or `null`. The mutmut id, the Stryker id, the bare function name, and `file:function` no longer match. `bob waive` accepts only a target of a survivor in `.bob/mutation-cache.json` or `.bob/stryker-mutants.json`, and exits `4` with nothing written for any other target. The Stryker gate writes `.bob/stryker-mutants.json`. In TypeScript, a line inserted above a waived mutant changes its description, so that waiver stops matching and the gate exits `3`. Sixteen rows in bob's own `.bob/waivers.yaml` were migrated to the exact form. The `failure_text__mutmut_8` row was removed because that mutant is killed.

O id de um waiver de mutação é `arquivo::função`, para todo sobrevivente da função, ou `arquivo::função::<descrição>`, para um sobrevivente ([#25](https://github.com/fazedordecodigo/bob/issues/25), [ADR 0006](docs/adr/0006-chave-estavel-do-waiver.md)). A descrição é o operador do mutante sem espaço nas pontas: o diff do `mutmut show` no Python, e `{mutatorName}@{linha}:{coluna}-{linha}:{coluna}` mais ` -> {replacement}` quando houver, no TypeScript. A forma exata só existe quando nenhum outro sobrevivente da função tem a mesma descrição. A primeira coluna da tabela de sobreviventes passa a ser Alvo, e `survivors[].target` no `report.json` traz o mesmo valor ou `null`. O id do mutmut, o id do Stryker, o nome nu da função e `arquivo:função` não casam mais. `bob waive` só aceita o alvo de um sobrevivente de `.bob/mutation-cache.json` ou `.bob/stryker-mutants.json`, e sai com `4` sem gravar nada com outro alvo. O gate do Stryker grava `.bob/stryker-mutants.json`. No TypeScript, uma linha inserida acima de um mutante com waiver muda a descrição, então esse waiver deixa de casar e o gate sai com `3`. Dezesseis linhas do `.bob/waivers.yaml` do próprio bob foram migradas para a forma exata. A linha `failure_text__mutmut_8` foi removida porque esse mutante está morto.

The mutate gate exits `3` only for an unwaived survivor on a changed line. An unwaived survivor on a line the diff did not change stays in the report, marked outside the diff, and does not change the exit or the review focus. A survivor with no file, or with a line at or below zero, still exits `3`. Remutation is unchanged: a changed function, and a cached function that still has an unwaived survivor, are still mutated. The cache does not store `blocking`.

O gate mutate sai com `3` só para um sobrevivente sem waiver numa linha alterada. Sobrevivente sem waiver numa linha que o diff não mudou fica no relatório, marcado fora do diff, e não muda o exit nem o foco do review. Sobrevivente sem arquivo, ou com linha menor ou igual a zero, continua saindo com `3`. Every report includes a Churn section before the reproduce footer. When the typing gate, the secrets gate, or the dead-code gate ran, those sections come first. It counts the commits `git log` lists for each changed file inside `paths.include`, across `churn.window_days` calendar days (default 90) ending on the commit's own date. Each file also has a relative rate: changed lines in the diff divided by the number of lines in that file. The rate is null when the file has no lines or cannot be read, and the commit count stays. Markdown shows the rate to 4 decimal places. A changed function's hotspot is the commit count times its cyclomatic complexity. The section does not change the exit code. When the count cannot be read, the heading stays and the numbers do not. `schema_version` stays 1. The JSON field `churn` is optional in the schema and is always written. Omitting `churn`, or writing `churn: null` or `churn: {}`, keeps 90. `churn.window_days` set to `null`, a float, a bool, zero, or a negative integer exits 4 with English stderr and writes no report. Any other `churn.*` key does the same through the unknown-key path.

Todo relatório inclui a seção Rotatividade antes do rodapé de reprodução. Quando o gate de tipos, o de segredos ou o de código morto rodou, essas seções vêm antes. Ela conta os commits que o `git log` lista para cada arquivo alterado dentro de `paths.include`, em `churn.window_days` dias de calendário (padrão 90) terminando na data do próprio commit. Cada arquivo também tem uma taxa relativa: linhas alteradas no diff divididas pelo número de linhas desse arquivo. A taxa fica nula quando o arquivo não tem linhas ou não pode ser lido, e a contagem de commits permanece. O Markdown mostra a taxa com 4 casas decimais. O hotspot de uma função alterada é a contagem de commits vezes a complexidade ciclomática. A seção não muda o código de saída. Quando a contagem não pode ser lida, o título fica e os números não. `schema_version` continua 1. O campo JSON `churn` é opcional no schema e sempre é escrito. Omitir `churn`, ou escrever `churn: null` ou `churn: {}`, mantém 90. `churn.window_days` com `null`, um float, um bool, zero ou um inteiro negativo sai com 4, stderr em inglês, e não grava relatório. Qualquer outra chave `churn.*` faz o mesmo pelo caminho de chave desconhecida.

Uma instalação seguinte apaga uma dessas pastas só quando o `NOTICE` dela é um arquivo regular com os bytes que o instalador antigo copiava do pin `49dd158d1076134a641b33efb035946536778336`. Um `NOTICE` que é link simbólico não conta, mesmo quando aponta para uma cópia desse arquivo. Um arquivo, um link simbólico ou uma pasta que só divide o nome ficam, e o instalador avisa no stderr. Ele copia o `LICENSE` e não copia o `NOTICE`. Uma segunda execução deixa a mesma árvore e os mesmos avisos.
